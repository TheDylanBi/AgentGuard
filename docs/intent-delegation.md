# 任务范围内的参数委托与资源披露

本增量仅扩展 AgentDojo/pi 的 review 实验路径，采用原始用户请求作为授权根。
没有恢复“任务开始由模型枚举全部工具参数”的做法，也没有把工具返回值升级为用户命令。

## 任务范围与查询依赖

`policy/delegation.py` 的不可变 `IntentScope` 保存原始请求、可信上下文和任务身份。
每次审查绑定本次完整参数、状态及原生证据引用，并区分读/查候选与带写入效果的候选。
这些元数据均为 `requires_current_call_review`，`necessity_proven=false`。
它提供了统一的任务根与依赖表达，不是把自然语言编译成了形式化授权规则。

审查器可以将“为用户指定的操作解析必要参数”识别为合理查询，而不要求用户逐个点名工具。
每次仍须判断查询必要性、资源范围、隐私和完整效果；相关链接、已读消息和工具名称不能自动提供授权。
没有增加仅按 read/list/search 类型放行的捷径。

英文月份的明确日期及同年日期范围增加确定性转换，要求出现年份并校验真实日历日期。
转换只产生日期候选，不决定哪个值是起止日期，也不补出时刻、时区或缺省年份。
跨年含义不明的范围不会推断另一个年份；用户条件和否定仍须审查。

文档原生正文可以按可信声明抽取邮箱候选，标记为不可信数据；邮箱出现不证明它属于用户要求的客户。
原生字典也可通过 `result_values.extract=mapping_keys` 登记键的字面来源，例如文件共享成员地址。
共享关系证明该地址出现在共享元数据中，不能证明它与指定客户的身份关系；权限值、自由文本 JSON
和任意模型声明不能代替原生键凭据，收件人关系仍需当前调用的语义审查或可信确认。
create 工具可声明 `new_identity_fields`，仅让原生文本中有字面来源的新名字进入当前调用审查。
这与已有资源的身份绑定不同，不能要求尚未创建的对象先存在于目录。

`created_identity` 声明将获准的创建参数绑定到原生集合：只有执行无错误、该值此前不存在且执行后确实存在，
宿主才发放新身份的事实凭据。成功文本或未经执行的参数不能发放凭据。
该事实凭据可以供下一次操作验证身份出现，不能继承创建操作的授权；后续加入频道等操作仍单独审核。

对 URL 与句号后新句紧贴的歧义，原有严格边界证明保留；新增的是显式标注歧义的审查候选。
该候选 `source_verified=false`，不能被视为已证明的用户网址，必须引用原始用户请求进行当前调用审查。
这一路径不推断新的域名、协议降级、查询参数、凭据或私有 IP。
普通合法精确 URL 仍走原有路径；其他无来源地址仍缺少证据。
真实网络适配器仍需独立处理 DNS、重定向、出站数据和网络能力范围，词法解析不能证明远程地址安全。

## 资源附件

新增可信清单声明 `resource_flows`，与具体任务编号、评分答案和固定文件 ID 无关。
示例：

```json
{
  "resource_flows": {
    "attachments": {
      "type": "file",
      "key": "file_id",
      "tag_field": "type",
      "tag_value": "file",
      "reason": "Bind native resources and require per-call disclosure review"
    }
  }
}
```

声明必须绑定工具 Schema、已注册的资源类型、control 参数和单独的数据使用审查。
Workspace 邮件适配器已按其真实工具实现声明文件附件；其他工具可通过相同声明接入。
此配置描述工具如何引用资源，不授予发送任何文件的任务权限。

宿主逐个验证附件列表，限制数量、重复项及支持变体的字段形状。
每个文件必须有本任务实际原生结果的凭据，并匹配当前实体哈希、账户命名空间和有效期。
文件选择不明确时仍需语义审查；明确不匹配的文件不能进入放行路径。
其他未声明的联合类型变体不取得新凭据或污染例外，继续受原有检查约束。

原生文件 ID 在附件位置表示披露该文件内容，不是普通身份引用。
新增 `taint_flow_fields` 仅由可信宿主从已验证资源位置构造，允许进入当前调用的数据使用审查；
它不构成执行许可。`check_hard` 仍只返回 PASS/BLOCK/CONFIRM。
文件 ID 出现在正文、其他参数或未声明位置仍受原有直接污染限制。
会话污染状态保持；能力和独立业务禁止规则仍先于审查生效。

审查包的数据使用范围包含资源版本、账户哈希、转换方式、完整 To/CC/BCC、参数和状态。
放行要求总体 allow 与 data_use_decision=allow，并引用原始用户和每个附件来源观察。
审查结束后再次检查版本和硬约束，授权不能复用为该工具的永久权限。
宿主只证明“此次将披露什么”；是否获得用户授权仍依赖可信审批或语义审查。
测试明确展示错误审查器仍可能把用户禁止的附件披露误放行，不能据此宣称形式化语义安全。

## 金融参数委托

复用现有 Decimal 证据图和显式受限审批，不从自由文本账单自动生成付款权限。
可信审批中的收款方现在既可为显式固定值，也可引用已观察且仍有效的原生交易账户字段。
后者必须产生 account 类型、单一原生字段来源的证明；用自由文本或常量伪装成账户推导会被拒绝。
金额、付款日期、整个动作参数、账户、效果、次数及来源重复消费限制继续核对。

原生证明保证与任务内银行查询和当前记录相符，不等于现实银行的账户归属/KYC 证明。
允许委托的是可信审批中指定的求值规则；审批不能由模型输出或账单中的新指令直接生效。
未明确授权的付款、任意补出的日期、仅来自自由文本的新收款账户，仍不能靠相关性或模型置信度放行。

## 恢复状态

对外 ALLOW/CONFIRM/BLOCK 保留原有执行含义；反馈增加内部状态与字段要求：

| 内部状态 | 含义 |
|---|---|
| NEED_EVIDENCE | 补充原生来源、目标身份或任务支持；相关查询仍需单独审核 |
| NEED_DERIVATION | 已有数值来源，但需要受支持的确定性计算及授权依据 |
| REPLAN | 修正参数或任务规划；反馈不授予新权限 |
| CONFIRM | 需要真实可信授权，不能用工具文本或自动同意替代 |
| BLOCK | 当前硬边界禁止 |

反馈不会自动调用查询、付款或计算器，也不会把 CONFIRM 自动转为 ALLOW。
“没有原文数值”和“已有输入但缺少计算证明”可以分别诊断。
已完成的 review v2 协议恢复继续使用，不增加有效拒绝的重新询问或无限重试。

## 如何验证

离线测试同时检查实际模拟器状态变化、收件人替换、来源缺失/过期、状态变化、必要证据引用、
同一 ID 在非附件位置的污染限制，以及错误语义允许的剩余风险。
正常任务诊断与攻击任务另存结果；没有独立标注就不推算语义误拒率或越权放行率。
小规模诊断不能替代全 97 项正常任务及固定攻击集。
