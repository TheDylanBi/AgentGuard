# 工具参数契约与调用前意图匹配

本层实现于 `policy/tool_contract.py`，可由不同工具适配器复用。目前已接入 pi–AgentDojo 的全部工具；生产 HTTP 网关和 NTFS 执行器仍使用其已有检查流程，不会因为新增模块而自动获得这层 schema 检查。

## 执行顺序

1. 从可信工具的 Pydantic 参数模型枚举所有参数、类型和默认值，建立契约。无需人工逐项填写敏感字段清单。
2. 检查已审核的 schema 哈希；工具定义变化时拒绝使用旧语义声明。动态默认工厂需要专门适配，不能静默接受。
3. 独立意图模型根据原始任务和可信工具描述生成规则。会话初始化时补充操作方审核过的默认值约束；不会读取后续模型调用来扩大规则。
4. 模型提出调用后，校验参数并补齐默认值。未知顶层字段会被拒绝，不静默丢弃。
5. 先执行原有授权检查，再要求同一条匹配规则覆盖全部最终参数。原有 BLOCK 不会被覆盖，原有 CONFIRM 不会被改成 ALLOW。
6. 将规范化参数与环境状态绑定后，由受控模拟主机调用官方 runtime。审计记录参数契约和执行参数哈希。

`eq` / `in` 的匹配还进行递归类型比较，避免 Python 将 `False` 与 `0`、`True` 与 `1` 视为同一个授权值。对象或数组参数可整体精确绑定；没有针对任意嵌套对象自动推断字段业务语义。

## 两种参数模式

### intent_bound（默认）

参数必须有用户意图对应的有限值约束；省略参数后填入的默认值也需要覆盖。没有写语义声明的参数自动采用此模式。

没有规则、规则只限制其他字段、OR 的某个接受分支没有约束此字段、或者只有宽泛 glob/contains 时，不会视为完整授权。尚不支持从数值上下界谓词推导意图覆盖；已有能力参数硬约束中的数值范围检查继续生效。

如果工具把某个参数明确映射为 `target` 或可信别名，只有对应值完全一致时，契约检查才承认该别名上的有限约束。核心策略的原有敏感字段检查保持独立，不因别名覆盖而被跳过。

### no_additional_effect（需操作方审核）

只用于具有静态默认值的可选参数。操作方必须显式提供允许值集合、语义依据和工具 schema 哈希。值可以是空值，也可以是经审核没有附加效应的非空值，例如某个工具的 `notify=false`；程序不会从名字或默认值猜测其安全性。

配置形式：

```json
{
  "schema_hash": "sha256:经审核的工具schema哈希",
  "parameter_semantics": {
    "notify": {
      "mode": "no_additional_effect",
      "values": [false],
      "reason": "已核对工具实现：false 不发送附加通知"
    }
  }
}
```

这只是工具条目中的相关字段示例，不能直接替换完整 manifest。声明按类型校验，必须覆盖实际默认值，必填参数不允许声明为可安全省略。

该声明只会给已有的具体工具 allow 规则补充 AND 约束，不新建工具授权。规则已提及字段时保留原约束，不擅自改成默认值；deny 和通配符规则不变。原来的 `optional_empty_values` 配置仍兼容，但新配置建议使用语义声明及 schema 固定。

## 本次接入范围

workspace 的 24 个工具、37 个参数已自动纳入检查。邮件的 cc/bcc/attachments 和日历创建的 description/location 已迁移为可信语义声明。其他参数并未自动宣布为“安全默认值”，而是默认要求意图约束。

新增工具的参数枚举、默认值补全、覆盖检查和类型校验不需要为工具单独写代码。但工具的能力、效应、来源、默认值的业务含义仍需要可信声明；空查询或 null 过滤器可能扩大数据范围，不能自动放行。

## 动态值与权限边界

本次没有实现“张三姓名 → 邮箱”“最新文件 → 文件 ID”等自动授权解析器。查询结果只是数据，不能因模型选择了某个 ID 就把该 ID 加入意图规则。缺少可验证的任务对象绑定时继续要求确认。后续接入解析器时必须验证来源、任务关系和资源身份，不能让注入文本生成新的权限。

生成摘要、任意新正文等未预先确定的内容也没有默认豁免。当前有限约束不足时保持确认；这可能降低任务完成率，应如实报告。此改动不保证全量评测不再触发轮数上限，也不包含断点续跑。

## 检查与审计

在项目根目录和 agentdojo 环境运行：

```powershell
python -B -m adapters.agentdojo_pi.run --mode guarded --check
python -B -m adapters.agentdojo_pi.run --mode guarded --check --describe-contracts
```

第二条输出每个参数的必填性、默认值、模式、审核值集合及 schema 哈希，不调用模型。

正式运行增加保存 `parameter-contracts.json` 和 `audit/policy-<会话ID>.json`。后者包含有效意图规则、效应画像及契约；它可能包含任务内容，应按任务日志管理。`summary.json` 保存对应快照哈希。原始模型提议继续保存在官方日志中，执行参数单独绑定。

修复前后检查更严格，比较实验时应使用相同代码、manifest、模型与任务集合重新运行 baseline 和 guarded，不混合统计不同版本的结果。

## 执行中才能确定的参数

任务内资源 ID 可通过可信声明和初始 allow 模板绑定，不需要新增工具名分支。详见 [动态绑定与工具接入](runtime-bindings.md)。绑定后的实际参数仍经过本契约检查。
