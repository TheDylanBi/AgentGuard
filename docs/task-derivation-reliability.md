# 任务参数推导与审查预算

本轮修复逐次 review 路径中的参数证据和运行预算。原生工具、AgentDojo 评分器与数据未改；
推导证明仍不等于任务授权。模型提出的操作继续通过硬边界、独立语义与数据流审查，并在执行前复核状态。

## 日期和时长

已声明的日历起止字段支持：

- 带年份的英文月份日期或 ISO 日期，以及同句中的 12/24 小时时刻。
- 同一条邮件的原生 timestamp 提供年月上下文，正文的星期和日号必须匹配该月实际日期。
- 起点加原始用户明确指定的小时/分钟时长，支持跨日和闰日。

来源日期、时刻、时长、原观察引用进入证据。邮件时间戳仅是正文日期的参考，不充当活动时刻。
不从不同句子借用时钟、不猜缺少年份、不抹去明确时区。无法解析的表达继续要求补证。
来源含有指令或否定时，独立审查仍须判断任务相关性，不能把文本出现当成授权。

改期工具也接入自然语言时间推导。新起点必须来自用户/有效来源；新终点可保留同一新鲜事件的原时长，
但改变时长仍需独立依据。目标事件的语义消歧、参与者和通知效应仍需审核。

仅给日期的提醒可配置一个共同时间窗口。Python CLI 默认关闭；本地启动脚本自 2026-10-24 起
默认使用 `09:00-10:00`，两种模式相同。例如：

```powershell
& '.\.local-qwen\run-qwen.ps1' -AllSuites -IntentFormat review `
  -CalendarReminderWindow '09:00-10:00' -ReviewThinkingMode disabled
```

此偏好只适用于用户明确请求提醒、提供日期且没有时刻的情况，不覆盖用户时间、不批准写入。
缺少年份时，只能使用干净模拟环境公开的 calendar.current_day 年份（workspace/travel 均读取）；
没有该时钟时继续要求澄清。不会从任务答案或事件内容取当前日期。
baseline 和 guarded 对照必须配置相同窗口。CLI 等价参数为 `--calendar-reminder-window 09:00-10:00`；
偏好同时进入两种模式的系统上下文、运行配置和 summary，比较器拒绝偏好不一致的对照。
本功能没有把原生日历时间段伪称为全天事件。

## 金额推导

`parameter_evidence.calculations` 是绑定原生 Schema 的可信适配声明，支持三种封闭语法：

- 已读取付款记录的原金额，加上明确的 `increase by N` / `increased by N`。
- 原交易金额减去用户明确说出的 `half the total of N`（或显式 half 加 spent N）。
- 原付款金额乘以用户给定的 `N% of`，再加 `fee of M`。

涨租增量可来自原始用户，或用户点名的原生虚拟文件。文件必须已经实际读取，当前内容哈希仍匹配。
源记录要求当前账户、唯一身份、类型、精度、有效期及完整原生记录版本一致。使用 Decimal，
不搜索运算和常数来凑模型提出的金额。不明确舍入时不自行舍入。
退款/附加付款的目标必须关联原生交易的付款方/收款方；新账单账号不能仅靠此功能取得来源证明。

计算结果和每个常数保留来源片段及原观察引用，独立审查继续判断操作、选择和用途。
付款日期和分摊方式可使用下述明确运行偏好；没有该偏好时保留原有严格行为。
可选更新字段维持原有省略/None 语义；不得为了完成任务额外修改 recurring、日期或收款人。
已支撑金融执行尝试的来源仍消耗一次，审查恢复不会重放付款。

## 审查预算与协议

默认每个拟执行调用的审查与恢复共用 45 秒预算，首次请求最多 30 秒，第二次使用剩余时间；
任务总期限前预留 15 秒。剩余预算不足 2 秒时不再发送审查请求。
超出预算的响应不能产生授权，错误单独记为 `review_budget_error`，不计成防御成功或官方评分失败。

配置环境变量：

```text
ICB_REVIEW_CALL_TIMEOUT_SECONDS=45
ICB_REVIEW_ACTION_RESERVE_SECONDS=15
ICB_REVIEW_MIN_ATTEMPT_SECONDS=2
```

启动脚本提供 `-ReviewCallTimeout` 和 `-ReviewActionReserve`。
传输超时、临时连接错误或 429/502/503/504 最多恢复一次；400、TLS/代理配置错误不盲目重试。
有效 deny/needs_evidence 仍为终局判断；含否定判断但格式无效的响应不重问以争取 allow。
恢复的是尚未执行调用的审查，不是原生写操作。

输出 Schema 约束 decision/code 配对。诊断区分决策值、决策码、请求绑定、数据流、字段和引用错误。
默认保留服务的推理设置；兼容 DeepSeek 顶层 thinking 协议的服务可显式设置
`-ReviewThinkingMode disabled`。这个选项不关闭行动模型推理，也不能证明关闭后语义准确率相同。

## 对照与验证边界

行动模型的比较提示在两种模式中一致：先过滤再排序、明确人数和餐次数、局部更新保持其他字段、
只根据成功执行记录声称写入完成。审查器提示同样区分必要候选查询与最终选择。
这不是任意自然语言任务的确定性比较编译器，也不是所有子任务完成性的证明。

本地状态测试覆盖日期转换、原生邮件上下文、金额推导、错误金额/目标/日期、源记录变化、
文件篡改、账户变更、过期、缺少引用、否定审查、业务禁止、重放、预算耗尽和协议恢复。
固定审查夹具只用于验证宿主边界，不测量真实模型的误放率或误拒率。

下一轮正式比较须冻结当前代码、模型设置、UTF-8 输入和偏好；同时保留正常任务、攻击任务、
未评分错误、CONFIRM、耗时。历史 89/97 baseline 与本轮代码不匹配，不能冒充严格配对结果。
评分公式与题意解释存在差异的题目保留原始官方分数，不把答案常数写入执行策略。

## 2026-10-24 正常任务恢复

本地脚本默认启用的共同偏好（baseline/guarded 一致）：

- `-CalendarReminderWindow '09:00-10:00'`：日期提醒的缺省时段。
- `-PaymentDatePolicy run-day`：用户已授权的即时付款/退款未给执行日期时，使用记录的运行日。
  有公开模拟日期时用模拟日期；banking 没有模拟时钟时冻结启动当天日期，不复制原交易日期。
  该执行日期单独存为 `payment_execution_day`，不会伪称为模拟当前日期；banking 默认的
  `trusted_current_day` 仍为空。不能用这个执行日期推断历史交易是否属于用户所指的“最近”交易。
  原始请求明确给日期、要求未来调度或存在相对日期冲突时不能用该偏好覆盖。
- `-EqualSharePolicy two-party`：用户明确与一个朋友共同用餐、只说 their share 且未规定其他分摊方式时，
  可按总额一半推导超付款退款。其他人数、不等额约定及不支持的表达不进入此规则。
- `-ReviewThinkingMode disabled`：当前 DeepSeek 审核服务的明确模式，保持本轮低延迟设置。

这些约定只补参数，不批准转账或写入；每次仍核对原始请求、业务边界、来源、账户和执行状态。
严格配置可用 `-CalendarReminderWindow '' -PaymentDatePolicy explicit -EqualSharePolicy explicit`。
CLI 对应 `--payment-date-policy`、`--equal-share-policy`，默认均为 explicit。
`--trusted-current-day` / `--trusted-current-time`（脚本同名 PascalCase 参数）允许明确设置实验时钟。
日期不含时刻；没有提供可信时刻时，倒计时任务仍不能凭评分答案猜当前时间。
偏好全部写入 summary 和配置哈希，比较器拒绝不一致的配对。

任务点名的模拟账单，可从唯一的 Total 和 IBAN 标签提取金额/收款账户。
账单必须实际读取、原内容哈希仍匹配；歧义、篡改、过期、替换金额/账户和重复付款均不获放行。
该证明只证明对应关系，付款目的及文档指令的授权范围继续由独立审核判断。

Slack 聚合证据只统计已执行读取的原生消息 sender 字段，不统计正文中的名字或计数声明。
完整频道清单、所有频道读取、当前内容哈希及 300 秒有效期均进入证明。计数降序/姓名升序的序号
提供给行动模型及审核器；是否符合用户要求、是否允许发消息仍独立判断，不自动覆盖 deny。

文件 inventory 行动视图保留全部条目的 ID、名称、所有者、时间、共享信息和大小，正文按 ID 读取。
收发邮件 inventory 同样保留所有行及邮件头、主题和附件，正文按主题检索。
原生返回、资源收据、审核观察在宿主中保持完整；行动目录省略仅供审计使用的重复哈希/引用元数据。
行动上下文仅去掉较早含工具调用的 assistant 消息中的计划文字，保留所有原始用户文字、
工具调用及结果、最终答案和推理签名。原会话不变；过去 usage 已无法度量改变后的前缀，
只在发送视图的副本中作废，让 SDK 按完整新上下文重新估算并保留原有 4096 token 安全余量。
真实 usage（包括缓存 token）仍记录到诊断。无额外摘要模型调用，也不扩大 SDK 上下文/输出上限。
文件读取说明还要求：通讯录没有条目时，检查任务文件原生 shared_with 元数据与正文中的人员上下文。
保留原始地址及域名，不把少见拼写自动“纠正”为相似域名。共享身份只证明地址来源；
具体人员匹配、消息内容和通知范围仍须独立审核，不能把共享成员一律当成收件人。
联系人按姓名/邮箱查询还声明了本账户 contact_list 的原生只读命名空间；
这让审核器能区分必要的联系人解析与后续发送效应。声明不会证明查询必要、不会自动放行，
更不会把一次查询的 CONFIRM 变成所有其他操作都要重新批准。
SDK 拒绝未声明位置的资源引用时，现在按无效工具参数反馈、消耗原有最多 3 次参数纠错预算；
不执行该调用，也不把这种模型参数错误当作宿主流程崩溃。若 SDK 拒绝的是宿主确认有效的引用，
仍报告协议故障，不绕过 SDK 执行。`get_file_by_id` 的原生 ID 参数和接受引用的其他参数保持区分。
banking.read_file 的参数说明明确区分模拟文件键和主机路径：直接使用用户给定的键，
不拼接 SDK 的临时工作目录、盘符，也不自动取 basename 来绕过边界。模拟映射边界保持原样。
SDK 只剩少量输出（例如 52 token）且截断时，现在明确记录为上下文预算错误。

两个旅行费用题的文字与官方计算口径存在冲突；不改评分器、餐费单位或写入已知答案来抬分。
