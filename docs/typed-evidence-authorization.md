# 类型化证据与显式审批（review 实验模式）

此次增量采用“程序证明计算，审查器判断剩余语义”的思路，但不让模型自动创建权限。
任务开始仍不生成参数计划。默认仍为 rules；以下机制首先接入 AgentDojo/pi 模拟宿主。

## 已实现的路径

1. 宿主从声明过、绑定 Schema 的原生工具结果中登记交易字段。返回实体必须与当前模拟环境中的唯一实体完全一致；字符串中声称存在的交易不能取得凭据。
2. `policy/typed_evidence.py` 以受限表达式执行 Decimal 加减乘除、显式舍入和日期加减，记录输入调用、字段路径、记录哈希及运算节点。限制账户、精度、记录版本、有效期和表达式规模。
3. `policy/scoped_authorization.py` 匹配由用户或管理员明确选入的审批：原始请求哈希、账户或命名空间快照、操作、资源类型、全部有效参数、目的地、完整效果上界和次数必须吻合。
4. 匹配后仍复核能力、Schema、业务规则、资源和数据流硬约束。执行前再次核对状态与计算依据，消费单次许可。明确审批不允许审查器扩大范围。
5. 没有显式审批时，继续采用原来的逐次语义审查；金融派生参数不会仅凭模型同意而放行。存在适用审批但参数/证据不符时直接拒绝，不能再用模型同意绕过。

金融审批要求显式固定收款人，或可信审批指定的原生交易账户字段绑定；同时要求正数金额计算证明及明确日期。对金融交易输入在当前任务内记录已消费身份，重复读取或换一份审批不能再次使用相同输入付款。执行失败仍消费尝试，避免不确定结果下重复付款。

## 使用入口

普通 review 验证无需新增参数：

```powershell
& '.\.local-qwen\run-qwen.ps1' -AllSuites -IntentFormat review
```

确有额外的可信审批时，显式指定文件：

```powershell
& '.\.local-qwen\run-qwen.ps1' -IntentFormat review -AuthorizationContracts 'F:\approvals\approved.json' -Check
```

`-Check` 只做配置和审批文档结构检查，不验证服务连通性，也不证明审批能够匹配将来的调用。去掉 `-Check` 才运行任务。
直接 Python 接口是 `--authorization-contracts PATH`，只允许 `--mode guarded --intent-format review`。
文件不能来自工具结果、行动模型输出或未经用户认可的审查器提议。结果目录保存文档快照与哈希。

文件格式为 `{"version":1,"contracts":[...]}`；空数组不授权任何操作。
每个契约必须包含以下全部字段，不接受未声明字段：

| 字段 | 含义 |
|---|---|
| `id`、`reason` | 唯一审批编号与可信审批理由 |
| `request_hash` | `attestation.hashing.object_hash` 对原始请求字符串的结果 |
| `namespace` | `{"path":[...],"equals":"账户"}` 或 `{"path":[...],"sha256":"命名空间快照的 object_hash"}` |
| `operation`、`resource_type` | Schema 绑定的规范化动作与资源类型 |
| `effect_upper_bound`、`destinations` | 必须与完整规范化调用严格一致；无目的地时为 null |
| `parameters` | 覆盖全部规范化有效参数，包括默认值；每项为 `{"eq":值}` 或 `{"derive":表达式}` |
| `max_uses`、`scale` | 执行尝试上限 1–20；金额小数精度 0–6 |

这里匹配的是规范化字段，原始工具字段名由可信声明映射。字段值不匹配时不会替行动模型改参数。
这是额外审批接口，不是为 benchmark 填答案的配置。使用额外审批会改变授权条件；比较报告会拒绝将不同审批配置直接当成同条件防御对照。

## 计算表达式

以下仅演示语法，不是已批准的任务或默认业务规则：

```json
{
  "op": "subtract",
  "inputs": [
    {"source":{"label":"bank_transaction","key":5,"field":"amount","where":{"sender":"approved-account"}}},
    {"literal":"6.00","type":"money"}
  ]
}
```

`source` 只能引用本任务已登记且当前有效的原生记录；`where` 精确匹配字段，不执行自然语言选择。
常量的权威来自显式审批，而非出现在网页/账单文本中。
`add/subtract` 要求类型一致，`multiply/divide` 的右操作数必须是 ratio；除零、负金额、跨账户、不符精度均拒绝。
非整分计算必须显式使用 `{"op":"round","input":表达式,"rounding":"half_even"}` 或 `half_up`。
日期支持 `{"op":"date_add_days","input":{"literal":"2024-02-28","type":"date"},"days":2}`。

原生声明见 banking manifest 的 `typed_results`：绑定集合、唯一键、账户路径、字段类型及精度。
声明定义结果的可验证结构，不证明账单真实、税率适用或付款业务正确。

## 指标与验证边界

summary 的 `authorization_diagnostics` 新增审查次数、模型请求数、错误率、弃权率、截断恢复、契约执行尝试、复用率及授权路径占比。
复用率是同契约第二次及以后执行尝试/契约执行尝试，不能与“无需模型审查的路径占比”混为一谈。
没有独立标注时，误拒率、越权放行率为 null；提供标注后，它们只覆盖模型逐次审查调用，
不覆盖契约路径和硬检查。不能拿审查器自己的答案或任务完成评分充当授权真值。
离线接口 `review_metrics(runs, labels={request_id: bool})` 接受独立逐调用标注。

当前测试验证了执行约束和官方模拟器状态变化，并不证明普通审查模型具有正确语义判断能力。
没有重新跑完 97 项正常任务或攻击集，不能宣布整体完成率或防御效果改善。
没有自动从自然语言账单编译收款人、税率、日期或审批；原来的某些金融任务仍可能因证据不足而受控停止。

AgentDojo 银行模型没有 ISO 币种字段，因此这里只使用任务内账户单位，不能声称验证了人民币/美元或汇率换算。
去重是任务内机制，不是跨进程持久幂等；模拟宿主串行复核也不是远程真实支付系统的原子事务。
生产接入仍需独立的认证审批、账务事实校验、额度/余额规则以及支付端持久幂等保证。

## 能力兼容性修复

支付效果现在要求独立的 `financial_transfer: allowed`，默认 denied。
`external_share: allowed` 不再隐含付款能力；已有支付工具需在可信能力声明中显式迁移。
Banking 模拟工具已更新。能力声明仍不代表用户授权，不能单凭这个标记付款。
