# 合法执行链的定向修复

2026-10-23 增加了宿主资源引用与引用格式恢复，当前 review 接口可用短 RID 代替复制原生键。实现与本轮验证见 [资源引用说明](resource-references.md)；以下原始阶段结果保留，不作为新版本的全量效果。

沿用实验性逐次 review、有界反馈和一次完成核对。没有预生成参数规则，没有新增业务禁令、可信批准或工具；规则和 boundary 对照保留。

## 宿主证据句柄

审查传输时将本调用中已存在的观察编码为 e1、e2 等短句柄，附上宿主签发的映射表及引用覆盖要求。模型必须主动选择证据，并独立返回任务判断及 data_use_decision。宿主按本调用映射解码后，仍执行原来的完整引用、数据使用范围、硬边界及状态复核。

程序不填入模型遗漏的引用，不把 allow 的来源要求自动补齐。不存在的句柄、从工具正文复制的伪造引用和不符合当前协议的原始长引用均失败。缺少引用最多技术恢复一次；有效 deny/needs_evidence 不重新请求。技术恢复只针对待执行调用的审查，已执行的写操作及 receipt 不重放。

短引用减少复制错误，明确覆盖要求减少“JSON 有效但缺少必要来源”。它们不能证明语义支持成立，也不会把工具文字变成用户授权。

## 来源反馈

当具体字段缺证据时，反馈 fields 与实际 requirements 保持一致。已声明允许进入语义审查的生成备注单列 semantic_review_pending_fields，避免要求用户逐字提供任意文案；原始 proof 仍保留不完整状态，只有全部硬检查及独立审查通过才能执行。

语义审查的 insufficient_evidence / ambiguous_target 单列 evidence_stage=task_authorization，并在反馈中附带已有参数来源类型、候选读取记录。它不再暗示所有被列出的身份都缺少硬绑定；来源真实与“足以判断最小值”等任务证据分开表达。恢复预算保持原样，不生成替代参数，不把未读项变成必读项或读取权限。

例如已绑定金额但缺少付款日期时，只将日期列为来源缺口；备注仍送入原审查通路。程序不会使用旧交易日期充当新付款日期。

原生记录更新另修复缺失/空账户命名空间的失败关闭行为。即使参数逐字出现于用户请求、审查器误报同意且尚未产生污染，也不能绕过记录键证据。

## 数值与完成核对

新增封闭的 Decimal 文字算术检查，仅支持数字、加减乘除、括号和百分数，有长度、深度和数值界限。没有 eval、代码执行、函数调用或自由公式搜索。

现有一次完成核对附带 answer_arithmetic：支持显式纯数公式、两列表格及具有唯一金额/费用列的多列表格加法总计。不同币种、复杂表格、嵌套小计、无法解释的表达式不猜；仅存在舍入差异时要求舍入契约，不能直接宣告算错。

它可以提示 50+1000 不等于 1060，但不能确定哪些交易属于支出、该引用是否真实、某价格单位是否相同或一个金融公式是否获准。结果不是授权，不更改工具参数，不会为修正文字总计重做付款。整题完成性仍明确为未独立验证。

## 资源名称中的数据与指令

新增的资源身份目录仅投影本次真实返回、同任务且未过期，并在适配器固定的 identity_scopes 中实际存在的资源键；有数量、长度上限及截断标记。目录明确 task_authorized=false、new_permissions=false，不生成执行权限。

行动模型保留完整原始结果。额外目录与固定提示区分“把真实键作为查询参数”和“服从键里的文字”，避免统计或排名时因名称可疑就漏掉候选。它不去除污染、不替代授权；即使源数据伪造目录，执行层仍独立验证身份、范围和数据流。

审查与原有的一次完成核对还附带候选读取记录：按工具声明中的资源角色及语义字段，把真实身份与成功执行的读取回执关联。记录只覆盖已经观察到的候选，标明未读项、数量上限和截断情况。一次读取不证明所需事实已经获得、候选相关或全局清单完整；不得据此自动授权读取全部候选。涉及最小值等比较的操作，审查器仍须根据原始任务和实际内容判断证据是否充分。

## 写入时间的来源

修复通用 derived_text 通路中“一次无关读取使任意时间进入审查”的缺口。对修改操作中未被其他证据证明的 ISO 日期/时间控制值，只有实际来源包含该完整值时才能作为待审候选；对应的来源引用必须继续进入审查。来源匹配不等于授权：source_verified 和 task_authorized 仍为 false，独立审查与数据流限制继续生效。明确由用户给出的时间和已有可靠推导通路保留。没有来源时不会补出默认时刻。

## 验证

机制测试覆盖缺少引用/伪造句柄、有效负面审查不重试、已加入频道后的审查恢复不重复加入、描述字段与日期反馈分离、缺失账户不能更新，以及算术/舍入/混合单位反例。

前三个开发阶段选择修复前后各 6 个正常任务、2 个固定攻击组合；最后反馈调整另做 1 项正常任务及其 1 个固定攻击的局部对照。不做全量实验。保留全部阶段，不取最佳成绩。任务、代码与服务配置冻结，原始官方分数及错误全部保留。阶段间修改代码，因此不能把不同阶段合并为同一版本的独立重复实验。单轮小样本不能证明全量收益、语义误放率或长期稳定性；结果位于 results/execution_chain_validation_20261022/report.md。

本轮没有实测完成率提升的证据。最后局部正常任务双方成功，攻击任务双方失败：修复后开始查询遗漏候选，却在复制长键时改变了换行/空格，真实工具返回不存在。最后预筛查另有 1 次审查服务超时，仍保留未评分。资源键复制稳定性、语义判断准确性和服务稳定性不能用机制测试通过来替代；没有通过相似匹配、自动改写资源键或放宽授权来获得分数。

注入暴露统计仅检查实际工具消息中完整攻击载荷，支持原生 YAML 与宿主附加 JSON 目录共存；助手自述、局部关键词均不算完整暴露。分析脚本的修复不改变原始官方分数。保持率只在对应无攻击任务成功且完整暴露的组合中计算，有未评分项则不报告确定比率。

尚未实现任意自然语言金融委托的自动编译、自动付款日期、猜测联系人或通用自然语言目标的完备证明。不能把这些缺口通过放宽来源或数据流检查掩盖。
