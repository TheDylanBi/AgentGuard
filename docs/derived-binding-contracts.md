# 派生文本与结构化委托的接入约束

这两项能力通过现有 `bindings` 声明接入，核心引擎没有工具名称或任务编号分支。默认不开启；声明也不能单独授予任务权限。初始规则必须显式引用相应绑定，并授权完整、确定的源查询参数。

## 1. 来源文本按固定模板组合

在绑定声明中增加：

```json
{
  "require_source_arguments": true,
  "derivation": {
    "kind": "text_template",
    "parts": [
      {"literal": "来源摘录：\n"},
      {"path": ["body"]}
    ],
    "max_chars": 4096
  }
}
```

这是现有完整绑定声明的扩展片段，仍须提供 `source_tool`、`source_path`、`source_arguments`、`target_tool`、`target_field`、TTL、使用次数和审核理由。`source_path`（以及可选 selection）先选出一个来源值；模板中的 path 相对于该值。目标参数必须是字符串。

宿主提取指定字段，逐字组合常量和来源文本，最终工具参数必须与宿主计算出的值相同。支持根路径 `[]`，不支持通配符、表达式、代码执行或缺失字段回退。最多 32 个片段，最大输出 16384 字符。来源中的指令、占位符或 `$binding` 文本保持普通字符串，不再次解释。

这解决可确定的摘录、复制与模板报告。它不证明文本事实正确、适合公开，也不证明任意模型摘要或建议安全。数据流仍需要单独声明和授权，原有直接 taint、目标和收件人检查仍有效。

## 2. 文档中的结构化请求

在另一个绑定声明中增加：

```json
{
  "require_source_arguments": true,
  "derivation": {
    "kind": "structured_call",
    "bounds": {
      "destination": ["authorized-destination"],
      "content": ["choice A", "choice B"],
      "enabled": [false]
    }
  }
}
```

`bounds` 必须覆盖目标工具的全部参数，包括默认值；每个参数只能列出有限、类型精确的备选值。这些边界由运营者审核，与初始任务规则共同限制后续调用。参数之间有关联时，还应在初始规则中约束完整组合；单独的字段集合本身不表达关联。

被授权源工具返回并由 `source_path` 选出的值必须是对象：

```json
{
  "tool": "the_declared_target_tool",
  "arguments": {
    "destination": "authorized-destination",
    "content": "choice B",
    "enabled": false
  }
}
```

工具名称必须与绑定的 `target_tool` 相同。宿主先检查整个对象和全部参数，再提取本绑定的 `target_field`。不接受额外字段、缺省参数、类型转换、自然语言命令、代码围栏或多个请求。不会从文档添加 allow 规则，更不会执行文档给出的工具名称。

要绑定多个字段，应分别声明到相同授权来源的绑定，仍在同一初始 allow 的组合条件中引用。文档请求即使在运营者的 bounds 内，也不能突破更窄的任务规则、deny、能力或实际效果限制。读取文档而没有目标工具 allow 时，不会因此获得执行权。

当前不自动解析普通邮件/文档正文中的自然语言请求，也不自动决定其授权含义。这部分仍需要初始授权范围表达与可靠的结构化提议流程，不能声称已经通用解决。

## 3. 审计、生命周期与接入步骤

1. 声明源工具、目标工具和参数；检查 Schema、数据流、目标及实际效果语义。
2. 原始用户任务必须支持该用途；意图规则使用普通 `$binding` 引用及完整 `source_arguments`，不在规则中自行创建模板或 bounds。
3. 已获授权的读取成功后，宿主计算候选值；仅物化现有规则中的引用，不增加权限。
4. 工具调用经过原有所有检查后才执行。TTL、状态绑定、次数、跨任务隔离继续有效。
5. 审计保存来源调用、来源值哈希、派生值哈希和声明哈希。即使派生文本相同，来源值改变也会使该绑定失效；重读不能刷新它。

未修改 workspace manifest 自动启用这些能力，也未提供修复后的外部模型成功率。应先审核接入声明，再进行真实评测，避免把框架测试通过当作 benchmark 提升证据。

## 4. 本轮验证记录

- 项目虚拟环境的受控执行 26 项、安全加固 45 项通过。
- 新增场景覆盖模板篡改、工具替换、参数越界、类型混淆、来源替换、任务范围收窄、污染与显式拒绝。测试使用通用虚构工具，不使用 benchmark 期望答案修正生产逻辑。
- 外部 DeepSeek 实测未运行：先前自动审批要求明确的数据外发授权，本轮未绕过该限制。
