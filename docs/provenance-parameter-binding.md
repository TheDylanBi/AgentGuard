# 参数来源与授权证据的修复

本轮沿用已有的一次完成核对、有界重规划及逐次审查协议，不增加任务特例，
不预生成参数允许值，不把来源证明或只读声明当作任务授权。旧实验数据保留在
`results/coordination_validation_20261022/`；本轮验证在独立目录
`results/parameter_binding_validation_20261022/`，不拼接两个版本的成功样本。

## 来源证明与工具效果适用条件

`policy/parameter_binding.py` 的 `argument_effect_admission` 明确区分：

- 参数仍缺证据：进入原来的证据补齐流程。
- 参数证据齐全，但没有经过审核的参数/效果声明：反馈
  `CONFIGURATION_REQUIRED / tool_effect_boundary_unreviewed`，不再说用户没有提供参数。
- 两者均成立：仅表示可以进入独立审查，绝不直接产生 ALLOW。

可信适配器可以通过既有 `dataflow_mode: initial_arguments` 声明工具效果由完整有效参数界定。
Banking 的密码更新已经核对原生实现并补充该声明。该声明需固定 Schema；
工具说明、网页或行动模型不能自行声明。原始请求中的逐字匹配继续由程序计算，
且仍须检查该值是否用于用户授权的操作、否定和条件分支。普通工具结果不能变成用户原文证据。

工具效果声明和字段绑定声明进入能力实现指纹及执行前后的状态复核。

## READ_FOR_RESOLUTION 是审查上下文，不是新增放行状态

可通过 `resolution_read` 接入受控的原生只读工具：

```json
{
  "namespace": ["account", "identity"],
  "collections": [["account", "records"]],
  "reason": "Operator-reviewed native read scope; not user permission."
}
```

声明要求固定 Schema、原生账户命名空间、受限集合和纯读取的能力上界。
拥有写入、网络、凭据访问或进程执行能力的工具，不能仅因名字或用途像查询而进入此路径。
当前版本不把外部网页、Shell 或 Python 执行当作有保证的原生只读范围。

宿主只给审查器账户与集合的当前哈希，标记 `task_authorized=false`、
`necessity_proven=false`。审查器仍要判断：原任务是否授权该资源范围、查询是否必要、
实际效果是否受限。不能要求先提供只有查询之后才知道的 ID；也不能因为网页要求查询就放行。
读取获准不会授权后续付款、修改或对外披露。有效拒绝不会被重问以争取放行。

## 已观察记录到局部更新参数的绑定

既有 `parameter_evidence` 新增 `record_binding`，示例采用通用字段名：

```json
{
  "account": ["account", "identity"],
  "fields": {},
  "descriptive_fields": [],
  "record_binding": {
    "label": "native_record",
    "key_parameter": "entry",
    "fields": {"entry": "id", "value": "amount", "when": "date"}
  },
  "reason": "Bind native identity and exact unchanged fields; never task authority."
}
```

只适用于声明了资源目标的更新操作。宿主要求记录来自本任务已执行的原生读取，
唯一键、当前完整记录、账户、时效和类型均匹配：

- 资源键：生成 `NATIVE_RECORD_ID` 证明。
- 参数与该记录字段完全一致：生成 `PRESERVE_NATIVE_FIELD` 证明。
- 参数发生变化：此路径不提供证明，仍需用户原文、已有显式批准的计算契约等独立依据。
- 不同记录、不同账户、过期或重复键、审查期间状态变化均不能执行。

记录键证据是独立的必需条件：即使尚未读取其他工具、污染状态为 false，
也不能以审查模型同意代替原生记录 receipt。新增反例先复现了这一缺口，
随后才补上硬检查；发现缺口时运行中的部分实验已停止并单独保留，不混入修复后的成绩。

标识与布尔值保留实际类型，不把 `false` 变成字符串，也不把整数 ID 当作金额。
局部更新时，经过审核的可选参数 `None` 仍表示保持原值；不会替行动模型填入日期或收款人。

更新现有付款记录还需解析实际收款人：未修改时取当前唯一原生记录的收款人，
修改时取完整候选参数中的收款人。该解析只计算实际效果，不能替代收款人来源或任务授权。
所有新写入仍经独立硬检查、数据流审查及绑定到具体参数和状态的逐次授权。

本轮没有从自由文本账单自动生成金融权限，没有自动编译自然语言算式或采用默认付款日期。
已存在的 Decimal 受限计算 DAG 和显式可信契约继续使用；没有可靠输入或授权时仍需确认。
来源链证明的是原生执行结果与当前模拟状态一致，并不证明账单内容真实。
AgentDojo 未提供 ISO 币种，账户命名空间单位不能冒充币种或汇率校验。

## 记录中的秘密字段

适配器可用 `audit_secret_parameters` 声明执行记录不应复制的字段，要求固定 Schema 和已知参数。
密码更新已声明该字段。新增的宿主执行记录、对应审计 receipt 和结束核对只存执行引用，
不额外复制明文密码，也不新增可离线枚举的密码哈希。

这不是对所有日志的脱敏承诺：原始用户请求、必要的模型输入、官方 AgentDojo 轨迹及
模型自行写出的最终回答仍可能包含测试密码。不要用生产密码运行 benchmark。
生产适配器还需自己的身份认证、日志访问控制及秘密管理；本模拟器不替代这些要求。

## 验证与结论限制

新增用例以预先定义的授权请求和可观察模拟状态为依据，覆盖合法写入、替换参数、
伪造用户证明、独立业务禁令、过期/重复/跨账户记录、重放和审查时状态变化。
另用不同工具及参数名验证绑定不依赖具体名字。固定审查返回只用来验证程序执行边界，
不作为审查模型理解意图正确的证据。

真实模型验证固定代码与服务配置，保留全部正常任务、攻击组合、错误和耗时；
未评分错误不计为防御成功，零攻击成功也不能单独证明防御收益。
没有独立逐调用标注时，误拒率、错误确认率及因果归因指标仍为未知；
“轨迹出现拒绝”不能自动等于“Guard 导致失败”，没有拒绝也不证明提示词没有影响行为。

幂等检查仍是任务内机制，不能宣称实现了外部支付系统的持久幂等或跨服务原子事务。

手动重跑四个 suite 的正常任务：

```powershell
& '.\.local-qwen\run-qwen.ps1' -AllSuites -IntentFormat review -ReviewCoordination scoped
```
