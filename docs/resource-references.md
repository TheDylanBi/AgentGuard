# 资源引用：精确身份传输

本轮采用附件中优先级最高的 RID 思路，先修复资源键被模型改写的问题。实现位于 `policy/resource_handles.py`，目前接入 AgentDojo/pi 的 guarded/review 路径。rules、boundary 和 baseline 沿用原生参数接口。没有新增工具或可信批准。

## 调用方式

已声明的资源字段在模型接口中允许原生值或引用对象，例如：

```json
{"channel": {"$icb_resource_ref": "rid_任务随机标识_4"}}
```

真实引用由宿主在工具返回后签发，不能使用上例占位符。工具结果中的资源目录提供可直接使用的 `argument` 对象。每个引用对应精确原生值；包含换行、空格、大小写和 Unicode 的键也按原值解码。普通字符串保持原样，不做模糊匹配、空白修复或 Unicode 归一化。

引用对象不能再编码成一个 JSON 字符串。对包含当前已知引用、且不是该原生范围内真实身份的错误字符串，宿主返回 quoted_reference 格式反馈，不自动解包或执行。若真实原生键本身恰好等于这种 JSON 文本，则仍按原生字符串处理，避免改错目标。正文等未声明位置不解析 JSON 字符串。

原始工具结果仍完整保留。因此攻击载荷仍可能暴露，不能把提供引用当作已清除注入。目录中的 preview 是不可信数据；引用只证明身份，不证明任务相关性、归属或执行权限。

## 声明接入

使用现有且已绑定原生 Schema 的声明：

- `observed_parameters` 加 `identity_scopes`：已观察并存在于固定原生集合的字符串身份，限 resource/destination 角色。
- `resource_parameters` 加 `provenance_resources`：已观察、当前实体及账户一致的原生记录键。
- `parameter_evidence.record_binding` 加 `typed_results`：复用现有类型化证据图，包括整数记录 ID，并检查账户、实体版本和有效期。

工具名、参数名不参与特例分支。新工具需有可信身份声明；只有 Schema、自由正文或模型声称的身份不足以签发引用。未声明原生身份范围的 URL、邮箱、金额、日期和正文不自动获得引用接口。

当前引用接口支持字符串、整数及其列表位置；复合对象身份需要单独的可信适配声明，不能假设所有任意 Schema 都自动支持。

`$icb_resource_ref` 是协议保留字段。在未声明位置直接放置含该字段的对象会被拒绝；原生 JSON 数据本身需要该保留字段时，应另做数据编码适配，不能当作资源引用传递。

## 执行边界

流程为：模型提议 → 校验引用所属任务/类型/有效期/原生快照 → 恢复原生参数 → 原有 Schema 与硬检查 → 独立语义审查 → 硬检查和引用复核 → 执行原生工具。

审查器、效应解析、收件人限制、数据流和执行绑定均使用恢复后的参数。引用不清除 taint、不覆盖业务禁令、不产生持久权限，也不绕过拒绝重放检查。不同引用解码成同一被拒绝调用，仍按同一原生调用处理。有效拒绝不会因引用存在而重新请求审查模型。

资源引用与证据句柄、授权完全分离。`e1` 不是资源引用，RID 不是授权凭证。本轮不新增 GID。

## 生命周期与记录

引用只存在于一次 query 的宿主内存；不能跨任务复用。实体或账户变化会使相关引用失效；集合型身份按声明集合快照绑定，集合变化需要重新观察。有效期内同一身份保持稳定，重读不会延长旧引用有效期。原生快照能证明的范围取决于适配器声明，不应推断额外的租户或所有权保证。

注册表最多 1024 项，每次目录最多 32 项，资源数组最多 24 KB（另加固定协议字段），键最长 16384 字符；达到上限明确标记 truncated。目录不是全局清单，读取回执不是完整任务证明。现有候选读取记录额外带 resource_argument，便于补读；没有自动读取或自动选定目标。

已成功解码的 AgentDojo 历史使用原生参数，避免官方评分器看到接口包装对象。签名宿主审计保留模型原始参数哈希、引用映射、恢复后参数哈希及状态哈希；run 结果记录解析成功、拒绝、晚期失效和执行尝试。原始协议和原生调用可以通过映射重建核对，不能用“已解析”冒充“已执行”或“任务完成”。

## 验证与保留的问题

定向测试使用真实原生状态和实际执行结果作为断言，覆盖恶意长键、Unicode、真实 pi SDK、整数 ID、类型/任务/账户隔离、过期、容量、业务禁令、能力撤销、晚期失效及同调用重放。测试中的审查器是固定夹具，只验证执行约束，不衡量语义判断准确率。

真实 SDK 测试还检查后续模型请求中的工具调用历史，确认引用仍是对象。第一轮真实模型确实通过 RID 完成了长键读取，之后却把引用写成字符串并在其他调用中复制坏了原名；本轮没有证据归因于 SDK。格式反馈增量另行冻结、测试和记录，不覆盖第一轮失败。

每轮真实模型对照固定为一个正常任务和它的一个攻击组合，修复前后各一次。第一轮使用上一轮最后的冻结代码作对照，格式反馈增量以第一轮 RID 代码作对照。模型接口增加了明确的引用分支，这是第一轮的实验干预；原生工具 Schema 和评分器未变。配置、代码、完整暴露、错误、实际调用及分数均单独记录，不合并版本、不挑选最佳尝试、不运行全量 97/560。

附件提出的比较/排序任务谓词、可信时间默认和全任务 obligation ledger 本轮不全面引入。已有类型化算术继续保留；现有日历 API 没有声明 all-day 或用户可知的默认时间，不能自行配置 09:00 来提高分数。资源引用也不能证明最小值、价格单位、日期授权或任务完整性。实验结果见 `results/resource_reference_validation_20261023/`。
