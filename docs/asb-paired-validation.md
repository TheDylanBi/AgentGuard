# ASB 执行补全与工具信任的配对验证

默认仍为 `--recovery native`。新增 `--recovery checkpoint` 是独立的任务结束检查实验，不改变原生任务、工具参数或官方评分。

## 任务步骤检查

检查输入为原始请求、宿主提供的可信问答、实际调用证据、完整历史和不可信工具目录。模型返回：

- `complete`：模型认为无需额外查询，不是独立完成证明。
- `propose_queries`：至多两个未尝试查询的规划提案，不是权限。
- `needs_clarification`：记录缺少的字段及理由，不代填公司、季度、账户或其他值。
- `uncertain`：不执行额外操作。

程序拒绝非协议字段、替代参数、未知工具和不存在的证据引用。重复提案只保留一次，已尝试的同名调用（包括拒绝和证据不足）不再重试。有可信契约的操作如果包含修改、交易、共享等额外效果，不属于此查询补全模式。操作标签“read”不能消除其副作用。

未知能力保持未知；没有独立契约且未开启严格契约要求时，仍是原有的有限来源语义审查设置，不能宣称新增查询已被证明只读。所有提案经过同一执行入口和原有任务授权；开启严格契约要求后，缺少来源证明的工具在语义模型前被阻断。

追加查询使用原生 `final_stage=False`，保留 OPI 注入和原始观察，不通过关闭攻击提高成绩。调用后至多一次最终回答；默认总计不超过两次额外行动模型逻辑请求，原有传输纠错预算保持不变。旧 `bounded` 实验也修复了跳过 OPI 和同批重复提案的问题。

`recovery.json` 和 `diagnostics.json` 保存检查状态、候选缺失信息、跳过原因和错误。模型的缺失信息判断也只是待核验判断，不证明环境确实没有这些信息。`calls.json` 的 `origin` 区分原生调用和补全调用；`result.json` 的 `trust_diagnostics` 单独统计没有独立契约的执行及来源阻断。

示例（沿用已有模型配置）：

```powershell
& '.\tmp\asb-venv\Scripts\python.exe' -X utf8 -B -m adapters.asb.run `
  --mode guarded --agent financial_analyst_agent --attack clean `
  --task-num 999 --limit 0 --recovery checkpoint `
  --tool-schema empty-object --skip-refusal-judge
```

## 来源先于用途判断

严格来源部署需要独立运维契约：

```text
--tool-contracts <独立审阅的v2声明.json> --require-tool-contracts
```

来源和能力声明要绑定实现版本、目录、运行时代码、实际实例、读取/写入范围和数据流。它们不能由正常/攻击标签、工具名称或模型解释自动生成；哈希匹配也不证明运维声明的语义正确。ASB 固定字符串接口没有真实资源选择器，不能证明金融业务能力或真实财务分析完成。详细格式见 [工具信任说明](asb-tool-trust.md)。

没有真实独立契约时，信任单项与组合消融应记录为缺少实验前提，不用“全部拒绝”的低攻击率充当有效防御。

## 固定重复与判据

[配对实验脚本](../results/asb_pairing_validation_20261026/validate.ps1) 默认固定 10 个攻击组合、5 个不同 clean 任务，两个重复轮次，关闭/开启检查分别运行 baseline/guarded。共 120 次任务执行，不是 120 个不同任务。选择包含已知失败，不能用于估计全量成功率。第二轮反转配置和模式顺序，降低服务随时间变化的影响；服务内部模型修订仍不能由客户端证明不变。

`adapters/asb/study.py` 只允许预先声明的消融字段不同，其他模型、接口、任务、源码、可信上下文和配置必须匹配。成功数/计划数、评分覆盖、未评分错误、收益/退化案例、新攻击成功、耗时和重复波动分别报告。未评分的对照不会被丢弃，均值不能掩盖某一轮退化。

原生 ASB 通过 `set` 构造工作流工具列表，因此复现时必须在解释器启动前固定 Python hash seed。
配对脚本已自动设置 `PYTHONHASHSEED=0`。手动运行时先执行：

```powershell
$env:PYTHONHASHSEED = '0'
```

结果同时保存 seed 和实际 hash 探针。探针只用于发现解释器启动配置漂移，不用于授权或密码学验证。
在 Python 已启动后修改环境变量不能重新设置其 hash 随机化；配对比较会检查实际探针。
这消除一个可控混杂因素，不保证远端模型输出确定，也不能证明旧结果波动全部由工具顺序导致。

完整阶段需要每轮都有明确收益、攻击下降且没有新成功案例、零异常和可接受的额外耗时，同时具备独立工具信任前提。即使通过小样本门槛，也只是允许进一步全量验证，不自动切换默认配置。正常查询遗漏、合理澄清和评分要求冲突要分别判断，不规定金融任务必须调用全部工具。

可信问答的补充任务使用独立协议，见 [任务上下文说明](asb-task-context.md)，其成绩不合并到原生 ASB。
