## 已实现的机制

- `--read-preflight`：可选的任务初始读取预检查。模型只能提出声明内的只读工具和符合 schema 的参数，程序将完整有效参数编译为有限授权。主规则中的拒绝条款继续有效。执行后不能借此新增权限。该功能仍依赖模型正确理解用户需求，尚未默认启用。
- 对象型工具不再把事件 ID 当作收件人。经审查的 manifest 声明允许宿主从当前模拟环境解析真实参与者，未解析成功则拒绝，已有收件人限制仍生效。
- 经声明启用的参数来源证明仅处理会话级间接污染导致的确认：参数必须满足初始有限授权，动态对象必须具有当前状态下的绑定记录。随后重新运行其余安全检查，直接污染、显式拒绝、业务规则仍有效。原会话污染状态不会被清除。该证明不证明自然语言条件或整个任务计划正确。

## 本次生成可靠性改动

新增可选环境变量 `ICB_INTENT_LLM_COMPACT_JSON=true`，必须同时设置 `ICB_INTENT_LLM_OUTPUT_FORMAT=vllm_guided_json`。它选择 vLLM Outlines 后端，并将 JSON 结构空白限制为 `[ ]?`，不改动字符串中的空格。参考 vLLM 0.8.5 的 Outlines 实现：
https://github.com/vllm-project/vllm/blob/v0.8.5/vllm/model_executor/guided_decoding/outlines_decoding.py

该选项默认关闭，服务不支持时不会静默退化为无约束输出。解析阶段仍拒绝 `finish_reason=length`，即使 JSON 表面完整也不接受。诊断新增原始字符数、首尾空白数和有效整数 token 用量，不保存响应正文或密钥；summary 记录紧凑模式配置。
